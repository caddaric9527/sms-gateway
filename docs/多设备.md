# 多设备支持（后端核心）

状态：后端已完成并用 3 台 mock 设备 + 1 台真机验证；**前端界面还是单设备视图**（第二步再做）。

## 怎么用

```bash
# 自动发现：留空端口，程序按 USB 拓扑识别每一台模块
MODEM_PORT=auto  MODEM_PORTS=  ...

# 手动指定：填了就只用这些口
MODEM_PORTS=COM7,COM10

# 没有硬件时联调多设备
MODEM_MOCK=1 MODEM_MOCK_COUNT=3
```

设备身份用 **IMEI**（`+STATUS` 里带回），不是端口号。端口只用于启动时建立映射。

## 关键设计（为什么这么写）

| 问题 | 处理 |
|---|---|
| 一台模块在 USB 上是复合设备，暴露 3 个串口 | 用 pyserial 的 `LOCATION`（USB 拓扑，如 `1-7`）把端口分组，一台一组；组内发 `PING`，回 `+PONG` 的才是数据口 |
| 热插拔后 `ttyACM*` / `COMx` 会漂 | 设备主键用 IMEI，注册表键用拓扑分组；端口每次启动重算 |
| 两台模块收到同一条短信 | 去重指纹混入 `device_id`，否则后到的那条被静默丢弃 |
| 长短信分片串台 | `concat_key` 前缀加 `device_id`，`merge_part` 只在同设备内找未完成的分片 |
| 一台发送卡 60 秒拖垮全局 | 每台一个独立串口驱动 + 独立轮询任务 + 独立同步锁 |
| 发送选哪台 | 指定 `device` → 已注册且有 SIM 的 → 任意连上的 |

## 接口变化（向后兼容）

- `GET /api/status`：顶层字段仍是「默认设备」，新增 `devices[]`（最多 20 项明细）和 `device_count`
- `GET /api/devices`：在线 + 历史登记的设备清单
- `GET /api/messages?device=<imei>`：按设备过滤
- `POST /api/messages`：body 可带 `"device": "<imei>"`，不传则自动选
- `POST /api/modem/resync|reconnect|at?device=<imei>`：按设备操作
- 转发 payload 新增 `device_id`

## 数据库迁移

`messages` 增加 `device_id` 列（`ALTER TABLE` 增量补列），新增 `devices` 表。
老数据 `device_id` 为空串 = 未知设备，不影响读；升级不需要清库。

> 注意：建索引必须放在补列**之后**，否则老库执行 `CREATE INDEX ... (device_id)`
> 会因为列不存在直接报错（已踩过一次，`tests/test_multi.py` 有回归用例）。

## 已知限制 / 下一步

1. **前端还是单设备视图**：状态卡、会话列表、发信弹窗都只看默认设备。需要加设备选择器 + 多状态卡。
2. **会话列表按号码聚合**（跨设备合并），暂未按设备拆分 —— 同一个人给两个号码发消息会合成一条会话。
3. **供电**：多台必须用带外置电源的 USB Hub。Air780EPM 发射峰值电流较大，NAS 直出的 USB 口通常只有 0.5A。
4. 每台都要烧同一份 `firmware/main.lua`，脚本没有设备相关配置，不用改。
